## What I will implement after your approval (smallest safe changes)
1. **P2-10, P2-11:** harden `readJson` in `_shared/http.ts` (JavaScript-compatible TypeScript as today: no new files in other languages); cap `departmentIds`; tests with real `Request`/`ReadableStream` objects, including a stream that would deliver far more than the limit and a check that the reader stops early.
2. **P2-13:** escape the reaction render; tighten the server-side emoji check; regression test on the rendering helper and on the server validation.
3. **P2-04, P2-05:** migration 026 (additive): client-scoped `assets_select` and the path-binding trigger; PGlite regression matrix (client department, uploader, admin, executive) plus the existing finance checks.
4. **P2-01:** a guard test that fails when a new hard-coded role list appears in an Edge Function.
Not changed without a decision: P2-02 (ceo parity), P2-06 (needs a live check), P2-09 (Drive), P2-03/P2-08 (optional).

## Behaviour changes to expect
- P2-04: staff outside a client's departments will no longer see that client's files in the library or in Storage (executives and the uploader still do).
- P2-10: oversized bodies get 413 earlier; legitimate requests are unaffected (largest legitimate body: finance invoices up to 200 KB).
- P2-13: reactions containing markup characters are refused by the server; existing stored ones render as text.
